이 프로젝트의 변경 사항을 리뷰하라.

`/CLAUDE.md`, `/docs/ARCHITECTURE.md`, `/docs/ADR.md`, `/docs/DATA.md`를 읽어 설계 의도를 파악한 뒤, 변경된 파일과 그 호출부를 확인하라. 사이트 변경이면 `/docs/UI_GUIDE.md`와 `/docs/COPY.md`도 읽어라.

## 체크리스트

1. **정확성**: 요구한 동작을 실제로 수행하는가? 경계 조건(빈 입력, 결과 없음, 타임아웃, 한도 초과, 중단된 생성 폴더), 에러 처리, 회귀 가능성을 확인하라.
2. **테스트 유효성**: 새 기능에 테스트가 있는가? 그 테스트가 실제 동작을 검증하는가(구현을 그대로 베낀 assert, 항상 통과하는 테스트는 아닌가)? 실제 CLI·API·네트워크를 부르거나 레포의 `results/`를 읽고 쓰는 테스트는 없는가?
3. **보안**: 결과물 iframe이 `sandbox="allow-scripts"`만 쓰는가(`allow-same-origin` 금지, 결과물 파일 직접 링크 금지)? 비밀값이 출력·커밋·자식 프로세스 환경으로 새지 않는가(API 키 변수 제거, `--bare` 금지)?
4. **아키텍처 준수**: ARCHITECTURE.md의 구조·의존 방향(`pipeline → core`, `site → core`)과 ADR의 기술 선택을 따르는가? 스키마·표시 규칙이 core 한 곳에만 있는가? 벗어났다면 합당한 이유가 있는가?
5. **CRITICAL 규칙**: CLAUDE.md의 CRITICAL 규칙을 위반하지 않았는가?
6. **데이터·문구**: 저장 데이터가 DATA.md(정규화 규칙·불변식)와 맞는가? 사이트 문구가 COPY.md와 글자까지 같은가? 모델 수를 하드코딩하지 않았는가?
7. **빌드·테스트**: `npm run lint`, `npm run typecheck`, `npm test`(사이트 변경이면 `npm run build`, results 관련이면 `npm run check:results`)가 통과하는가? 직접 실행해서 확인하라.
