# PRD: One Prompt Bench — 요구사항과 일정

## 목표

같은 프롬프트("사계절이 바뀌는 3D 나무")를 여러 LLM에 한 번씩 보내, 받은 결과물(단일 HTML)을 브라우저에서 나란히 실행·비교하는 정적 웹사이트 MVP를 만든다.
참고한 사이트: https://outliner-coach.github.io/aquagarden-bench (같은 과제를 여러 모델이 만든 결과를 하나씩 실행해 보는 방식, "순위가 아니라 기록").

- 용도: 포트폴리오, 개인 기록·갤러리
- **비용 원칙: 추가 결제 0원.** 현재 플랜(Claude Pro, ChatGPT Plus, Gemini API 무료 티어)만 쓴다. 이 원칙이 다른 모든 결정보다 앞선다.
- 방문자는 보기만 한다 (로그인·입력·댓글 없음).

## 사용자

| 사용자 | 하는 일 |
|---|---|
| 방문자 (포트폴리오 열람자) | 결과물을 하나씩 실행해 보고, 비교표·프롬프트를 읽는다 |
| 운영자 (본인 1명) | 생성 명령을 직접 실행하고, 결과물을 판정하고, 새 모델을 추가한다 |

## 핵심 기능

### 1. 생성 파이프라인 (운영자 PC에서 실행)
1. `models.json`의 모델마다 프롬프트를 1회 보내 결과를 `results/<slug>/`에 저장한다. 도구: Anthropic → Claude Code CLI, OpenAI → Codex CLI, Google → Gemini API.
2. 기술적 실패만 재시도하고, 응답이 온 경우(HTML 없음·거부·잘림)는 그대로 그 모델의 결과로 기록한다.
3. 생성 직후 Playwright 검증기가 자동으로 실행돼 열림·에러·외부 요청·스크린샷 4장을 기록한다. 전체 재검증도 할 수 있다.
4. 운영자가 판정 도우미(`npm run judge`)로 요구사항 4개를 판정하고 한 줄 메모를 남긴다.

### 2. 사이트 (탭 4개, 첫 화면은 결과 탭)
1. **결과**: 왼쪽 모델 목록(출시일 최신순), 오른쪽에 고른 결과물 하나만 실행. 다시 시작 버튼, 새 창에서 열기, 상태 표시, 요구사항 판정·메모, 생성 기록. 결과물이 없으면 이유와 응답 원문.
2. **비교표**: 수록 모델 / 생성 기록 / 요구사항과 검증, 표 3개와 각주.
3. **프롬프트**: 프롬프트 원문과 복사 버튼, 생성 조건, 판정 기준표.
4. **소개**: 확정 문구(`docs/COPY.md`), 수록 기준과 제외 모델.

화면 세부는 `docs/UI_GUIDE.md`, 문구는 `docs/COPY.md`, 표시 값 계산 규칙은 `docs/DATA.md`.

### 3. 배포
main에 push하면 GitHub Actions가 검사(lint·typecheck·test·results 검사)를 통과한 경우에만 GitHub Pages로 배포한다. 수동 실행 버튼도 둔다.

## MVP 제외 사항

- 검증의 로딩 시간·빈 화면 자동 판정·FPS 측정 (다음 버전 후보)
- 사이트에 스크린샷 표시 (판정·기록용 자료라서)
- 점수 합산·순위표
- 모델별 고유 주소(딥링크), 정상 결과의 응답 원문 보기, 푸터 (인터뷰에서 제외)
- 다국어, 다크 모드, 방문자 입력 기능, 분석 도구
- 새 모델 자동 감지 (반영은 수동)
- 한 모델의 여러 번 생성·평균 (모델마다 1회)

## 성공 기준

- 8개 모델 모두 생성 시도 기록이 있고(성공·실패 모두), 결과물이 있는 모델은 검증과 판정이 끝나 있다.
- 공개 URL에서 4개 탭이 동작하고, 휴대폰 화면에서도 쓸 수 있다.
- 생성에 추가 결제가 한 번도 발생하지 않는다.
- 일차별 개발 일지(`docs/devlog/day-N.md`)가 남아 있다.

## 일정 (5일 이내, 일차로 표시)

원칙: **얇게 끝까지 먼저.** 생성 → 검증 → 사이트 → 배포를 가장 단순한 형태로 먼저 잇고, 그다음 모델을 늘린다. 사이트가 일찍 공개되어 일정이 밀려도 공개된 링크가 남는다. 밀리면 범위는 그대로 두고 하루씩 연장한다.

일차 하나 = 하네스 phase 하나 (`phases/dayN-<slug>/`). phase가 끝나면 사람이 할 일을 한다.

| 일차 | phase에서 만들 것 (무인 세션) | 사람이 할 일 |
|---|---|---|
| 1 | 모노레포·core 연결, NestJS 뼈대, Gemini 어댑터, 일괄 실행(batch)·smoke 명령 | 추가 결제 차단 체크리스트, `.env`에 GEMINI_API_KEY, Gemini smoke → 1개 생성 |
| 2 | Playwright 검증기(생성 직후 자동 실행 포함), check:results, Astro 결과 탭 | 1일차 결과물 검증 실행, 결과 탭 로컬 확인 |
| 3 | GitHub Actions 배포 워크플로, Claude Code 어댑터 | 공개 레포 생성·Pages 설정·push(첫 배포), Claude smoke |
| 4 | Codex CLI 어댑터 | Codex smoke, 8개 일괄 생성과 검증 |
| 5 | 판정 도우미, 비교표·프롬프트·소개 탭, 휴대폰 화면, README | 8개 판정, devlog·회고 검토 |

각 일차가 끝나면 `/devlog N`으로 개발 일지 초안을 만들고 사람이 검토해 확정한다 (`docs/OPERATIONS.md`).
