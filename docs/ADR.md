# Architecture Decision Records — 결정과 이유

## 철학

1. **추가 결제 0원.** 현재 플랜(Claude Pro, ChatGPT Plus, Gemini 무료 티어)으로만 만든다. 다른 모든 결정보다 앞선다.
2. **기록의 정직성.** 모델마다 1회 생성하고 사람이 고치지 않는다. 도구마다 다른 조건은 숨기지 않고 각주로 공개한다. "순위가 아니라 기록"이다.
3. **얇게 끝까지.** 생성 → 검증 → 사이트 → 배포를 가장 단순하게 먼저 잇는다. 외부 의존성은 최소로 한다.

이 문서의 결정은 확정이다. 바꾸거나 여기에 없는 것을 정해야 하면 구현하기 전에 사람에게 묻는다(무인 step 세션은 설계 의도에 맞게 정하고 handoff에 남긴다). `(인터뷰)`는 2026-10-12 하네스 정비 때 사용자가 직접 고른 결정이다. `(기본값)`은 같은 때 Claude가 기획의 빈칸을 채운 결정이며, 사용자에게 보고했다.

---

### ADR-001: 생성은 구독 CLI와 Gemini 무료 API로
**결정**: Anthropic → Claude Code CLI(Pro 구독), OpenAI → Codex CLI(ChatGPT 로그인), Google → Gemini API 무료 티어. API 키는 `.env`의 `GEMINI_API_KEY` 하나만 둔다.
**이유**: 구독과 API가 따로 과금되므로, 추가 결제 없이 만들려면 각 회사의 구독 도구를 써야 한다. `ANTHROPIC_API_KEY`·`OPENAI_API_KEY`가 환경에 있으면 CLI가 구독 대신 API 키로 과금할 수 있어 두지 않는다.
**트레이드오프**: 도구마다 조절할 수 있는 조건(출력 상한, 추론 강도 단계, 시스템 프롬프트)이 달라 완전히 같은 조건을 만들 수 없다 → 각주로 공개한다. 구독 한도(5시간·주간)에 걸리면 기다려야 한다. Claude 모델 생성과 Claude Code 개발이 같은 Pro 한도를 쓴다.

### ADR-002: 사이트는 Astro 정적 사이트, 데이터는 빌드 때 읽는다
**결정**: Astro 정적 출력. `results/`·`models.json`·`prompts/`는 빌드 때만 읽는다. 런타임 API는 없다.
**이유**: 방문자는 보기만 하고 데이터는 생성 때만 바뀐다. GitHub Pages에 무료로 올릴 수 있다.
**트레이드오프**: 데이터를 바꾸면 다시 빌드·배포해야 한다 (main push로 자동).

### ADR-003: 파이프라인은 NestJS 스탠드얼론, 생성자 주입은 `@Inject(TOKEN)` 명시
**결정**: `createApplicationContext`로 서버 없이 모듈·DI만 쓴다. 생성자 주입에는 토큰을 명시한다.
**이유**: 사용자의 메인 스택이 NestJS/TypeScript다(포트폴리오). tsx(esbuild)는 `emitDecoratorMetadata`를 지원하지 않아 타입 기반 주입이 조용히 깨지므로 토큰을 명시한다 (기본값).
**트레이드오프**: 작은 CLI에 비해 구조가 무겁다. 그래서 도메인 로직은 core의 순수 함수로 두고 Nest는 얇게 감싸기만 한다.

### ADR-004: Runner와 Adapter의 책임 분리, 기술적 실패만 재시도
**결정**: Runner가 재시도·타임아웃·백오프·시간 측정·저장·비용 계산을, Adapter가 호출 1회·정규화·에러 분류만 맡는다. `timeout`·`rate_limited`·`server_error`·`network`만 재시도한다(최대 3회, 시도당 20분). 응답이 온 경우(HTML 없음·거부·잘림)는 재시도 없이 그 모델의 결과로 기록한다. `usage_limit`은 기록만 하고 다음 모델로 넘어간다. 다시 실행하면 실패한 것(`api_failed`)만 다시 돈다. 덮어쓰기는 `--force`일 때만 한다.
**이유**: 어댑터마다 같은 로직이 중복되지 않고, '기술적 실패'의 정의가 한 곳에만 있다. 인증 오류·잘못된 요청은 재시도해도 결과가 같거나 비용만 든다. 구독 한도는 몇 시간 뒤에야 풀린다.
**트레이드오프**: 응답 품질이 운에 좌우돼도 1회 결과로 남는다 (소개 탭 "순위가 아니라 기록"에서 밝힌다).

### ADR-005: 시스템 프롬프트는 세 도구 모두 같은 최소 지시문 (인터뷰)
**결정**: `prompts/season-tree-v1.system.md`("사용자의 요청에 답하세요.")로 Claude Code·Codex의 기본 지시문을 교체하고, Gemini에도 같은 문장을 `systemInstruction`으로 준다. meta.json의 `prompt.sha256`이 system과 user를 함께 해시한다.
**이유**: Claude Code·Codex의 기본 지시문은 코딩 에이전트용이라 결과에 섞이면 도구마다 조건이 달라진다. 비워 두는 방식은 도구마다 동작이 불확실하다.
**트레이드오프**: "도구를 그대로 썼을 때의 모습"과는 다르다. 지시문 교체가 실제로 적용되는지는 smoke로 확인해야 한다 (OPERATIONS.md ⚠ 목록).

### ADR-006: 생성은 격리된 환경에서 (기본값)
**결정**: 매 시도마다 빈 임시 디렉토리에서 실행한다. Claude Code는 `--safe-mode --tools "" --strict-mcp-config --no-session-persistence`, Codex는 `--sandbox read-only --ignore-user-config --ignore-rules --ephemeral --skip-git-repo-check`로 실행한다. 자식 프로세스 환경에서 API 키 변수를 지운다. Claude Code의 `--bare`는 쓰지 않는다.
**이유**: 레포 안에서 실행하면 이 프로젝트의 CLAUDE.md·AGENTS.md, 사용자 설정·메모리가 생성 맥락에 섞여 벤치마크가 오염된다. Codex는 에이전트라 응답 대신 파일을 쓸 수 있어서 쓰기를 막아 텍스트로 답하게 한다. `--bare`는 API 키 인증만 써서 과금된다.
**트레이드오프**: Codex가 read-only에서 파일 쓰기를 시도하다 실패하는 턴이 사용량에 섞일 수 있다.

### ADR-007: 출력 상한 65,536, Codex는 기록하지 않음(null) (null은 기본값)
**결정**: 출력 상한은 65,536 토큰이다(대상 중 최대 출력이 가장 작은 Gemini 3.8 Flash에 맞춤, 나머지는 128K). Codex CLI는 상한을 지정할 수 없어 모델 기본값으로 생성하고, `params.maxOutputTokens: null`로 기록하고 비교표 †로 표시한다. 추론 강도는 모든 모델 high이고, Gemini는 high가 최고 단계라 ‡로 표시한다.
**이유**: 모든 모델에 같은 상한을 줄 수 있는 가장 큰 값이다. 숫자를 지어내 기록하지 않는다.
**트레이드오프**: Codex 모델은 상한 조건이 다르다 (각주로 공개).

### ADR-008: 비용은 정가로 계산하고, 캐시 입력도 정가로 (캐시 처리는 기본값)
**결정**: `models.json` 정가로 계산하고 추론 토큰도 출력 단가로 계산한다. 캐시된 입력 토큰도 일반 입력 단가로 계산한다. 비교표에 "실제로는 구독과 무료 티어로 생성해서 청구된 금액은 없어요"를 붙인다. `pricing.asOf`로 가격표 시점을 기록한다.
**이유**: 실제 청구액은 0원이라 비교 가능한 기준은 정가뿐이다. 캐시 할인은 도구가 자동으로 적용하는 것이라 모델 간 비교를 흐린다. 1회 생성이라 캐시 비중도 작다.
**트레이드오프**: 실제 API로 같은 호출을 했을 때보다 조금 비싸게 나올 수 있다.

### ADR-009: 결과물은 `iframe sandbox="allow-scripts"` 안에서만 실행, 새 창은 래퍼 페이지 (래퍼는 기본값)
**결정**: 사이트의 모든 결과물 실행은 `sandbox="allow-scripts"` iframe이고, `allow-same-origin`은 넣지 않는다. "새 창에서 열기"는 결과물 파일이 아니라 같은 샌드박스 iframe을 화면 가득 띄운 `/view/<slug>/`로 연다. 한 번에 결과물 하나만 실행한다.
**이유**: 모델이 만든 코드는 신뢰할 수 없다. GitHub Pages는 계정의 모든 Pages 사이트가 `<user>.github.io` 한 출처를 쓰므로 샌드박스 밖에서 실행하면 다른 사이트의 저장소에 접근할 수 있다. 검증기도 같은 샌드박스에서 열어 실행 조건을 맞춘다. WebGL 장면을 여러 개 동시에 돌리면 무겁다.
**트레이드오프**: 정적 호스팅이라 결과물 파일 URL을 직접 열면 샌드박스 없이 실행된다. 직접 링크하지 않는 것으로 위험을 줄인다.

### ADR-010: 검증은 Playwright로 운영자 PC에서, 스크린샷은 WebP (sharp)
**결정**: 생성 직후 자동으로 검증하고 전체 재검증도 할 수 있다. 항목: 열림·콘솔 에러·페이지 에러·외부 요청·스크린샷 4장(5·15·25·35초, 각 계절 중간). Playwright가 찍은 PNG를 sharp로 WebP 변환한다 (sharp는 기본값).
**이유**: "계절마다 10초"를 스톱워치로 재지 않고 스크린샷이 맞는 계절인지로 판단한다. 로딩 시간·빈 화면 판정·FPS는 MVP에 과해서 뺐다.
**트레이드오프**: 검증이 three.js CDN 접속에 의존한다. 검증 1회에 40초 정도 걸린다.

### ADR-011: 조건 검사(외부 요청 판정)는 저장하지 않고 매번 계산
**결정**: `request-rules.ts`가 `validation.externalRequests`에서 매번 계산한다. three.js 본체·부가 모듈(버전 고정)은 정상, 버전 미고정은 지시 미준수, 다른 JS·이미지는 위반, 그 밖(폰트·스타일시트)은 참고로만 표시한다. 위반이어도 결과물은 그대로 보여주고 표시만 한다.
**이유**: 규칙이 바뀌어도 기록을 고칠 필요가 없다.
**트레이드오프**: 사이트 빌드 때마다 계산한다 (비용 무시할 수준).

### ADR-012: 판정은 사람이, 결과물 sha256에 묶어서
**결정**: 요구사항 4개 × ✓/△/✗와 한 줄 메모를 `judgment.json`에 기록한다(자동 기록인 meta.json과 분리). 판정한 결과물의 sha256을 적고, 빌드 때 결과물과 다르면 그 판정을 버린다. 메모는 사이트의 모델별 관찰 코멘트로 그대로 쓴다.
**이유**: 결과물이 바뀌었는데 예전 판정이 남는 것을 막는다.
**트레이드오프**: 결과물을 다시 만들면 다시 판정해야 한다.

### ADR-013: 판정 기록은 CLI 도우미로 (인터뷰)
**결정**: `npm run judge -- <slug>`가 sha256·판정 시각·프롬프트 정보를 자동으로 채우고, 사람은 요구사항 4개와 메모만 입력한다. 저장할 때 스키마로 검사한다.
**이유**: 판정은 새 모델이 나올 때마다 반복한다. sha256을 손으로 복사하는 실수를 없앤다.
**트레이드오프**: 작은 명령 하나와 테스트를 더 만든다.

### ADR-014: npm workspaces 모노레포, 도메인 로직은 core에
**결정**: `packages/core`(프레임워크 없는 도메인 로직: 스키마·러너·어댑터 인터페이스·추출·조건 검사·정렬·results 읽기·표시 규칙), `pipeline/`(NestJS, 실제 어댑터·batch·검증기·판정 도우미), `site/`(Astro), `results/`(결과물). 기존 runner·adapter 인터페이스는 core에 그대로 둔다 (기본값).
**이유**: 사이트와 파이프라인이 같은 스키마·표시 규칙을 써야 한다. 기존 코드를 옮기지 않아도 돼서 첫 phase 작업이 줄어든다.
**트레이드오프**: core에 node:fs를 쓰는 코드(runner, results)가 섞인다. 사이트는 빌드 때만 쓰므로 문제없다.

### ADR-015: 테스트는 가짜만, 실제 호출은 사람만
**결정**: 테스트 러너는 `node:test` + `tsx`다. 테스트는 가짜 어댑터·CLI 출력 fixture·로컬 HTML만 쓴다. 실제 생성 명령(`gen`·`smoke`·`claude -p`·`codex exec`·Gemini API)은 사람이 지시할 때 사람이 직접 실행한다. `.claude/hooks/block_dangerous.py`가 Claude 세션의 실제 호출과 `.env`·API 키 출력을 막는다.
**이유**: 개발 중에 실행하면 Pro·Plus 한도를 써 버린다. 무인 세션은 사람 확인 없이 돈다.
**트레이드오프**: 어댑터의 실제 출력 형식은 smoke 원본 출력을 fixture로 옮겨야 검증된다.

### ADR-016: 상태 라벨에 "거부"·"생성 실패"·"검증 전" 추가 (기본값)
**결정**: 기획 시안의 7개 라벨(정상·지시 미준수·위반·잘림·HTML 없음·한도 초과·생성 전)에 `refused` → 거부, `usage_limit`이 아닌 `api_failed` → 생성 실패, 검증 전 결과 → 검증 전을 더한다. 매핑과 색은 DATA.md·UI_GUIDE.md.
**이유**: 모든 outcome이 화면에 정확히 표시돼야 한다. 시안에는 해당 상태가 없었다.
**트레이드오프**: 없음 ("검증 전"은 배포 게이트가 막으므로 공개 사이트에는 나오지 않는다).

### ADR-017: 배포는 GitHub Pages + Actions, 검사를 통과해야만 (검사 항목은 기본값)
**결정**: 공개 레포다. main push와 수동 실행 버튼으로 배포한다. 배포 전에 lint·typecheck·test·check:results·build가 모두 통과해야 한다.
**이유**: GitHub Pages는 무료 플랜에서 공개 레포만 쓸 수 있다. check:results가 손으로 고친 결과물·깨진 기록을 막는다.
**트레이드오프**: CI에 Chromium 설치 시간이 든다 (배포 10분 제한 안).

### ADR-018: 스타일은 Astro scoped CSS + CSS 변수, UI 프레임워크 없음 (기본값)
**결정**: Tailwind·React를 쓰지 않는다. 상호작용(모델 전환·다시 시작·복사·드롭다운)은 Astro `<script>`의 순수 TypeScript로 만든다.
**이유**: 시안이 이미 구체적인 값(색·간격·둥글기)으로 되어 있어 토큰을 CSS 변수로 옮기면 된다. 의존성과 번들을 줄인다.
**트레이드오프**: 컴포넌트 상태 관리를 직접 한다 (범위가 작아 문제없다).

### ADR-019: 결과 탭 부가 기능은 "다시 시작"만 (인터뷰)
**결정**: 결과물을 처음(봄)부터 다시 실행하는 버튼을 더한다. 모델별 주소(딥링크), 정상 결과의 응답 원문 보기, 푸터는 만들지 않는다.
**이유**: 40초 순환을 처음부터 다시 보는 것이 결과물 감상에 가장 필요하다. 나머지는 MVP 범위를 넓힌다.
**트레이드오프**: 특정 모델 결과를 링크로 공유할 수 없다.

### ADR-020: 하네스 운영 — 개발 순서의 한 줄 = phase, 무인 세션은 Opus 5.5 (phase 단위·모델은 인터뷰)
**결정**: PRD "개발 순서" 표의 한 줄을 phase 하나(`phases/NN-<slug>`, NN은 표의 순서를 두 자리로)로 만든다. phase는 날짜와 묶지 않고, 개발 일지도 phase별(`docs/devlog/<phase>.md`)로 쓴다. phase index.json의 `model`은 `claude-opus-5-5`로 한다. execute.py는 Claude 구독 사용 한도 메시지를 감지하면 재시도하지 않고 step을 `blocked`로 멈춘다.
**이유**: phase 경계는 사람이 할 일(생성·배포 설정·판정)이 필요한 지점이다. 작업 속도는 날마다 달라서 날짜에 묶으면 계획과 기록이 어긋난다. 하네스 기록(index.json)이 phase 단위라 일지도 phase 단위가 맞다. 품질을 우선한다. 한도는 몇 시간 뒤에야 풀리므로 재시도는 시도 횟수만 낭비한다.
**트레이드오프**: Opus는 Pro 한도를 빨리 쓴다. Claude 모델 3개 생성분의 한도를 남겨 두려면 생성 전날 밤이나 한도가 리셋된 직후에 생성한다.

### ADR-021: "걸린 시간"은 마지막 시도의 소요 시간 (기본값)
**결정**: 비교표·결과 탭의 걸린 시간은 결과를 낸 마지막 시도의 `latencyMs`다. 재시도 횟수는 따로 표시한다.
**이유**: 백오프 대기와 실패한 시도를 빼야 모델의 생성 시간에 가깝다.
**트레이드오프**: CLI 도구는 프로세스 시작 시간(수 초)이 포함된다.
