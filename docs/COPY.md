# 사이트 문구 (확정)

사이트에 나오는 문구의 단일 출처다. 바꾸지 말고 그대로 쓴다. 바꿔야 하면 사람에게 먼저 묻는다.
- `{N}`은 빌드할 때 `models.json`의 모델 수로 채운다. 문구에 모델 수를 직접 쓰지 않는다(모델이 계속 추가된다).
- `(추가)` 표시는 기획 뒤에 빈칸을 채운 문구다(2026-10-12 하네스 정비, 2026-10-13 phase 2 확인). 나머지는 claude.ai 기획에서 확정한 문구다.

## 공통

- 사이트 이름: One Prompt Bench
- 헤더 부제: 하나의 프롬프트, 모델마다 다른 나무
- 탭: 소개 · 결과 · 비교표 · 프롬프트 (첫 화면은 결과). 헤더에는 페이지가 있는 탭만 이 순서로 둔다(ADR-024)
- 탭 목록(nav)의 aria-label: 주요 메뉴 (추가)
- `<html lang="ko">`, 페이지 `<title>`: `<탭 이름> — One Prompt Bench`, 결과 탭(`/`)은 `One Prompt Bench` (추가)
- meta description·og:description: 소개 탭 "제목 아래 문장" (추가)
- 판정 기호: ✓ 충족 · △ 부분 충족 · ✗ 미충족 · 판정 전
- 상태 라벨: 정상 · 지시 미준수 · 위반 · 잘림 · HTML 없음 · 거부(추가) · 한도 초과 · 생성 실패(추가) · 생성 전 · 검증 전(추가)
- 생성 도구 이름: Claude Code · Codex CLI · Gemini API
- 에러 종류 표시 (생성 실패 이유에 덧붙임, 추가): timeout 시간 초과 · rate_limited 요청 한도 · server_error 서버 오류 · network 네트워크 오류 · auth 인증 오류 · bad_request 잘못된 요청 · blocked 차단됨 · unknown 알 수 없는 오류

## 결과 탭

- 제목: 사계절이 바뀌는 3D 나무
- 설명: 같은 프롬프트로 여러 모델이 한 번씩 만든 결과물이에요. 왼쪽에서 모델을 고르면 그 결과물 하나만 실행돼요.
  - 휴대폰(드롭다운 화면)에서는 "왼쪽에서"를 "목록에서"로 바꾼다 (추가)
- 칩: season-tree-v1 · 모델 {N}개 · 모델당 1회 생성
- 목록 제목: 모델 / 정렬 안내: 출시일 최신순
- 범례 상자 제목: 상태 표시
- 목록 항목 보조 줄: `{회사} · {생성 도구}` (예: Anthropic · Claude Code)
- 실행 카드 머리: `{회사} · {생성 도구}로 생성 · {출시일} 출시`
- 버튼: 다시 시작 (추가) · 새 창에서 열기
- 카드 "요구사항 판정": 장면 · 계절 순환 · 계절 모습 · 계절 이름 (+ 판정 메모)
- 카드 "생성 기록": 결과 · 조건 검사 · 토큰 (입력 / 출력) · 비용 (정가 기준) · 걸린 시간
- 원문 카드 제목: 응답 원문 (추가)
  - 원문을 불러오지 못했을 때: 응답 원문을 불러오지 못했어요. (추가)
- iframe title: `{표시명} 결과물` (추가)

### 결과물이 없을 때

실행 영역에 라벨별 이유 문구를 보여준다. "원문"이 response.txt인 라벨은 실행 카드 아래에 응답 원문 카드를 둔다. 라벨을 고르는 규칙은 `docs/DATA.md` "상태 라벨"에 있다.

| 라벨 | 이유 문구 | 원문 |
|---|---|---|
| 생성 전 | 아직 생성하지 않았어요. | 없음 |
| 한도 초과 | 구독 사용 한도에 걸려 생성하지 못했어요. 한도가 풀리면 다시 생성해요. | 없음 |
| 생성 실패 | 기술적인 문제로 생성하지 못했어요. (+ 마지막 에러 종류, "공통" 절의 에러 종류 표시) | 없음 |
| 거부 | 모델이 요청을 거부했어요. | response.txt |
| 잘림 | 출력 상한에 닿아 응답이 중간에 끊겼어요. | response.txt |
| HTML 없음 | 응답에서 실행할 HTML 문서를 찾지 못했어요. | response.txt |

## 비교표 탭

- 제목: 비교표
- 설명: 모델마다 어떻게 만들어졌고, 얼마나 들었고, 프롬프트를 얼마나 지켰는지 나란히 봐요. 모델은 출시일 최신순이에요.
- 표 1 "수록 모델": 모델 · 회사 · 출시일 · 생성 도구 · 결과 · 파일 크기 · three.js 버전
- 표 2 "생성 기록": 모델 · 입력 토큰 · 출력 토큰 · 그중 추론 · 비용 (정가 기준) · 걸린 시간 · 재시도
  - 안내 박스: 비용은 API 정가로 계산한 값이에요. 실제로는 구독과 무료 티어로 생성해서 청구된 금액은 없어요.
  - 각주:
    - † Codex CLI는 출력 상한을 지정할 수 없어 모델 기본값으로 생성했어요. 다른 모델의 출력 상한은 65,536 토큰이에요.
    - ‡ Gemini 3.8 Flash는 추론 강도가 low·medium·high 세 단계라 high가 최고 단계예요. 다른 모델은 high 위에 단계가 더 있어요.
- 표 3 "요구사항과 검증": 모델 · 장면 · 계절 순환 · 계절 모습 · 계절 이름 · 조건 검사 · 에러 수
  - 범례: ✓ 충족 · △ 부분 충족 · ✗ 미충족 (사람이 판정) / 조건 검사: 정상 · 지시 미준수 · 위반 / 링크 "판정 기준 보기"

## 프롬프트 탭

- 제목: 프롬프트
- 설명: 모든 모델에 아래 문장을 한 글자도 바꾸지 않고 그대로 보냈어요. 레퍼런스 이미지는 없어요.
- 원문 카드: 칩 `season-tree-v1`, 버튼 "복사" → 복사 후 "복사됨"(추가). 본문은 `prompts/season-tree-v1.md` 그대로.
- "생성 조건" (라벨 / 값):
  - 횟수 / 모델마다 1회, 사람이 고치지 않음
  - 추론 강도 / high (회사마다 단계 구성이 달라요, 비교표 각주 참고)
  - 출력 상한 / 65,536 토큰 (도구별 차이는 비교표 각주 참고)
  - 생성 도구 / Claude Code · Codex CLI · Gemini API
  - 재시도 / 기술적 실패일 때만
  - 시스템 프롬프트 / "사용자의 요청에 답하세요." (모든 도구 같음) — (추가) 값은 `prompts/season-tree-v1.system.md`에서 읽는다
- "판정 기준" 설명: 결과물을 한 바퀴 넘게 지켜보고, 5·15·25·35초에 찍은 스크린샷 4장을 함께 봐요. "계절마다 10초"는 스크린샷이 각각 맞는 계절인지로 판단해요.
  - 표: 요구사항 · ✓ 충족 · △ 부분 충족 · ✗ 미충족. 내용은 `prompts/season-tree-v1.judging.md`의 표.

## 소개 탭

- 작은 라벨: AI 모델 결과물 비교
- 제목: 하나의 프롬프트, 모델마다 다른 나무
- 제목 아래 문장: 같은 프롬프트를 여러 AI 모델에 한 번씩 보내, 브라우저에서 바로 실행되는 3D 나무를 받았어요. 새 모델이 나오면 같은 프롬프트로 한 그루씩 더해요.
- 버튼: 결과 보러 가기(주) · 비교표 보기 · 프롬프트 전문
- 칩: 모델 {N}개 · season-tree-v1 · 모델당 1회 생성
- 카드:
  - What — **같은 과제, 다른 모델**: 2026년 9월 이후 출시된 OpenAI·Anthropic·Google 모델에 똑같은 프롬프트를 보냈어요. 지금까지 {N}개 모델이 참여했고, 새 모델도 같은 조건으로 추가해요.
  - How — **같은 조건, 자동 기록**: 모델마다 한 번, 추론 강도 high로 만들었고 사람이 손대지 않았어요. 생성과 검증은 프로그램이 자동으로 하고, 토큰과 시간과 에러를 기록해요.
  - Caution — **순위가 아니라 기록**: 모델마다 한 번씩만 생성해서 운이 섞여 있어요. 생성 도구마다 조건이 조금씩 다른 부분은 비교표 각주에 적었어요.
- 수록 기준:
  - 제목: 수록 기준
  - 문단: 2026년 9월 1일 이후 출시된 OpenAI·Anthropic·Google 모델이 대상이에요. 새로 추가되는 모델도 이 기준을 따라요.
  - "대상에서 뺀 모델":
    - Claude Mythos 5.1 — 처음부터 대상에서 제외
    - Claude Fable 5.1 — 사용 중인 구독 플랜에서 추가 결제가 필요해 제외
